# Identity

`buffr-laptop` is a private TypeScript personal RAG agent operated from a terminal chat UI. Its main surface is `npm run chat`, which starts an OpenTUI React session backed by Postgres/pgvector, local Ollama models, indexed personal knowledge, live connector tools, and decision/review workflows. The primary user is a single operator using their own notes, database rows, and live web signals to answer personal context questions, run market/product research, analyze investments, and revisit tracked decisions.

# Stack

The root package is ESM TypeScript with npm workspaces for `@buffr/contracts`, `@buffr/kernel`, `@buffr/connectors`, `@buffr/capabilities`, domain packs, and engines. Build/test commands are driven through `package.json`; chat compiles with `tsc` and runs with Bun because OpenTUI is the terminal UI runtime. Persistence is direct `pg` access to Postgres/Supabase with `pgvector`; model calls use Ollama for Gemma generation and nomic embeddings.

# Architecture

The root app composes infrastructure in `src/session.ts`: environment config, pg pool, `PgVectorStore`, `PgJournalStore`, retrieval pipeline, connector tools, model provider, prompt registry, trace sink, conversation memory, `RagQueryAgent`, `InvestingEngine`, and `MarketResearchEngine`. The UI layer in `src/cli/chat.tsx` only routes commands and displays progress; agent loop, retrieval, memory, and domain engines live in package workspaces. Data flows from markdown and configured external database tables into `agents.documents` and `agents.chunks`; chat answers and tool traces flow into `agents.conversations` and `agents.messages`; promoted research decisions flow into `agents.decisions`.

# Features

Stable features visible in code include markdown indexing (`src/cli/index-cmd.ts`), configured database row indexing (`src/cli/index-db-cmd.ts`, `src/db-sources.ts`), general RAG chat (`src/session.ts`, `packages/kernel/src/agents/rag-query-agent.ts`), pgvector retrieval (`src/pg-vector-store.ts`), trace persistence (`src/supabase-trace-sink.ts`), and eval commands (`src/cli/eval-cmd.ts`). More domain-specific features include `/research` with predict-then-reveal flow (`src/cli/research-flow.ts`, `packages/engines/market-research/src/engine.ts`), `/review` decision lifecycle (`src/cli/review-flow.ts`, `src/pg-journal-store.ts`), and `/investing` analysis (`packages/engines/investing/src/engine.ts`).

# Decisions

The code favors contracts and adapters: `VectorStore`, `DataConnector`, `Capability`, `Engine`, `JournalStore`, and `ModelProvider` separate orchestration from concrete IO. Retrieval memory is stored in the same `agents.chunks` table as knowledge, which keeps recall behind the existing `search_knowledge_base` tool and explains why `chunks.document_id` is a soft link. Scoring is deterministic in `Scorer`, while interpretation and synthesis are model-driven in `Analyzer` and `Teacher`. Connector results are cached in memory with short TTLs inside a single session.

# Incomplete And Deferred

The root session comment explicitly says sequential in-prompt turn history is still missing: `RagQueryAgent.answer()` treats each question independently and relies on retrieval memory instead. The chat agent constructs a Google Trends tool but excludes it from the general chat allowed-tools list because the underlying endpoint is frequently blocked. There is no RLS in the current database phase according to project context, and the SQL schema shows no auth policy layer.

# Risks And Rough Edges

The system depends on local Ollama availability, external connector availability, and a correctly migrated Postgres database. `src/session.ts` is a large composition root that also contains routing prompts, connector selection, topic suggestions, eval formatting, and command-facing formatting helpers. The vector schema fixes embeddings at `vector(768)`, so model changes require coordinated schema and code changes. Many writes are direct SQL without a migration table; migrations are an ordered hard-coded list.

# What's Next

Planning docs in `docs/superpowers/specs/` and `docs/superpowers/plans/` show recent direction around connector tools, capabilities, investing/domain-pack engines, OpenTUI migration, market research chat commands, and a thinking-session slice. The current code is organized around making the laptop app a local orchestration shell over reusable packages and domain engines.
